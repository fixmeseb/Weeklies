Building against this page's API

Every rule this form applies is applied by the JSON API too, and the contract is generated from the validator rather than written by hand, so it cannot drift from what the server accepts:

  • GET /api/restaurant/menu/schema — every field, whether it is required, and its vocabulary
  • GET /api/restaurant/menu — this restaurant's dishes
  • POST /api/restaurant/menu — add one; 201, or 422 with one message per bad field
  • PATCH /api/restaurant/menu/<itm_id> — change only the fields the body carries
  • POST /api/restaurant/menu/<itm_id>/stock — {"instock": false} takes a dish off the menu
  • DELETE /api/restaurant/menu/<itm_id> — 409 when a saved plan or order still names the dish
