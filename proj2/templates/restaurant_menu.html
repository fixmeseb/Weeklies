The same menu over HTTP

These pages are a client of an API, not a special case. Every rule the forms apply is applied here too, and the contract is generated from the validator rather than written by hand, so it cannot drift from what the server accepts.

GET    /api/restaurant/menu/schema          every field, whether it is required, its vocabulary
GET    /api/restaurant/menu                 your dishes
POST   /api/restaurant/menu                 add one — 201, or 422 with a message per bad field
PATCH  /api/restaurant/menu/<itm_id>        change only the fields the body carries
POST   /api/restaurant/menu/<itm_id>/stock  {"instock": false} takes a dish off the menu
DELETE /api/restaurant/menu/<itm_id>        409 while a saved plan or order still names it
